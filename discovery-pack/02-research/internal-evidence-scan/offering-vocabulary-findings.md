# 상품 vocabulary 조사 결과

- 작성일: 2026-08-24
- 근거: `source-register.csv`, `evidence-extracts.csv`
- 원칙: 실제 문서·메시지에 등장한 표기만 옮겼다. 정본에 없는 명칭도 관찰된 그대로 기록했다.

## 0. 가장 큰 발견

내부에는 세 개의 서로 다른 어휘 체계가 동시에 살아 있다.

| 체계 | 어휘 | 쓰이는 곳 | source |
|---|---|---|---|
| 과금 구조 어휘 | 모델 / 플랜 / 구독권 / 번개 | 제품·개발 내부 | S-011, S-052 |
| 대외 판매 어휘 | 기본 플랜 / 콘텐츠 이용권 | 2026-08-11 개편된 가격 페이지·문의 폼 | S-017, S-019 |
| 정본 어휘 | 코들 라이선스 / 코들 오리지널 콘텐츠 / 씨마스 인공지능 기초 | discovery-pack | 프로젝트 정본 |

세 체계가 같은 대상을 다르게 부른다. 예를 들어 하나의 씨마스 이용권이 내부에서는 `인기초 플랜`, 코드에서는 `cmass_ai`, 폼에서는 `씨마스 인공지능 기초`, 과거 폼에서는 `씨마스, 비상 플랜`으로 나타난다. 허브를 만들 때 이 셋 중 무엇을 최상위 label로 쓸지 owner가 정해야 한다.

## 1. 코들 라이선스 (P-001)

### 실제 사용 명칭·별칭

- `Pro 플랜`, `코들 프로`, `프로`, `PRO`, `코들 Pro Plan 학교용` `[source: S-019 / E-024]` `[source: S-062 / E-071]`
- `Basic`, `베이직`, `무료` `[source: S-011 / E-015]`
- 내부 전용: `모델`. `프로는 모델이고 AI 랑 씨마스 인기초는 기본적으로 거기에 더해지는 플랜입니다` `[source: S-011 / E-015]`
- 배정 단위 내부 은어: `구독권`, `번개` `[source: S-052 / E-057]`
- 2026-08-11 이후 대외 표기: `코들 구독 (Pro 플랜 + 콘텐츠 이용권)` `[source: S-019 / E-024]`

### 고객 표현과 내부 표현의 차이

고객이 폼에서 고르는 단위는 `학생 수 × 사용 학기 수 × 1인 기준가`다 `[source: S-019 / E-024]`. 내부 과금 단위는 `교실에 배정된 학생 수`이며 같은 학생이 두 교실에 있으면 두 번 차감된다 `[source: S-052 / E-057]`. 고객이 이해한 구매 단위와 시스템의 소진 단위가 다르다. 허브에서 `1인당`이라고 쓰면 이 간극이 계약 후 드러난다.

### 최상위 카드/탐색 label 후보

- `코들 라이선스` (정본)
- `코들 구독` (현행 폼 표기)
- `Pro 플랜` (현행 가격 페이지 표기)

### 아직 공개 카피로 쓰면 안 되는 표현

- 할인율. `50%할인` `[source: S-065 / E-074]`, `40% 할인율 보장` `[source: S-005]`는 개별 협상 결과이며 공개 승인이 없다
- `22,000원` 정가와 실판매가의 괴리. 실제 발행 건은 10,000원·13,000원 단가가 흔하다 `[source: S-062 / E-071]`
- `학교당 100만원` 같은 미확정 요금제 아이디어. `#t_제품_코들` 2026-08-06 게시물에서 관찰됐으나 D-hypothesis라 증거로 채택하지 않았다

## 2. 코들 오리지널 콘텐츠 (P-002)

### 실제 사용 명칭·별칭

- `AI 플랜`, `코들 AI Plan 학교용`, `AI 구독권` `[source: S-062 / E-071]` `[source: S-026 / E-032]`
- 2026-08-20 전후 변경된 대외 명칭: `Codle AI` `[source: S-018 / E-023]`
- 문의 폼의 콘텐츠 이용권 선택지 값: `Codle AI` `[source: S-079]`
- 정본 명칭: `코들 AI 콘텐츠 이용권` / `코들 오리지널 콘텐츠`

### 명칭 변경의 이유가 기록돼 있다

`콘텐츠 이용권을 따로 분리하다 보니 Cmass AI, AI 이렇게 표기되는게 약간 어색하고 혼돈되는 네이밍이라 혹시 기존 AI 플랜을 'Codle AI'로 변경해도 될까요?` `[source: S-018 / E-023]`

즉 콘텐츠 이용권을 상품으로 분리하자마자 명칭 충돌이 발생했고, 그 해결책으로 브랜드 접두어를 붙였다. 허브가 여러 콘텐츠 이용권을 나란히 놓으면 같은 문제가 다시 생긴다.

### 혼동되는 상품 관계

`AI 플랜 > PRO 이고 인기초 > PRO 인데 인기초와 AI 플랜 간의 관계성이 모호함. pro 는 더 낮은 등급이 맞고, ai, 인기초는 동일 등급인데 둘 안 선택 가능하며 중복선택도 가능해야함` `[source: S-077 / E-016]`

오리지널과 씨마스는 상하 관계가 아니라 동일 계층이며 중복 구매가 가능해야 한다는 내부 정의다. 정본에서 pending으로 남겨둔 `오리지널·씨마스 동시 구매 가능 여부`에 대한 내부 근거가 존재한다.

### 최상위 카드/탐색 label 후보

- `코들 오리지널 콘텐츠` (정본)
- `Codle AI` (현행 제품 표기)

`AI 플랜`은 이미 폐기 중인 명칭이므로 새 허브에 쓰지 않는다.

### 아직 공개 카피로 쓰면 안 되는 표현

- 콘텐츠 목록·갱신 주기 약속. 검색한 위치와 검색어에서는 확인되지 않았다
- `코들 Pro 콘텐츠`가 무엇을 포함하는지. 정본 O-005는 여전히 pending이며 이번 조사에서도 확정 근거를 찾지 못했다

파트너가 교사에게 실제로 보낸 문구는 콘텐츠 스펙이 아니라 교사 업무 부담이었다.

`학기말 생기부 작성 부담을 줄여주는 활동 자동 수집 / 실습 막힐 때 도움 주는 파이썬 오류 도우미 / 단원별 선생님용/학생용 화면 각각 제공` `[source: S-014 / E-019]`

### 혼동되는 상품 관계

- 총판 위탁 채널에서는 10,000원 단품을 팔 수 없고 30,000원 결합만 판다 `[source: S-010 / E-014]`

### 최상위 카드/탐색 label 후보

- `씨마스 인공지능 기초` (정본이자 현행 폼 표기, 일치함)

세 어휘 체계가 유일하게 일치하는 상품이다.

### 아직 공개 카피로 쓰면 안 되는 표현

- `국내 고교 정보 수업 점유율 1위` `[source: S-014 / E-018]`. 파트너의 주장이며 코들 화면에 그대로 옮기려면 별도 권리·사실 확인이 필요하다

## 4. AIDT 교육자료 (P-004)

### 실제 사용 명칭·별칭

- `AIDT`, `AI 디지털 교육자료`, `AI디지털 교육자료` `[source: S-040 / E-043]`
- 서비스 약관 제목: `AIDT 교육자료 서비스 이용약관` `[source: S-074 / E-086]`
- 출판사별 지칭: `금성 중등`, `YBM 중등/고등`, `AIDT 25-1 고등 정보` `[source: S-040 / E-043]`
- 배포 대상 코드명: `codle-react (AIDT)`, `aidt-user-rails`, `<tenant>.aidt.me` -> `edupath.kr`

### 고객 표현과 내부 표현의 차이

발행사는 자신을 판매자로, 코들을 데이터·플랫폼 공급자로 말한다.

`저희 YBM의 정보 과목 AIDT 는 이번 2026년에 총 2개 고등학교에서 구독하고 있습니다` `[source: S-042 / E-045]`

`구독하고 있습니다`의 주어는 학교이고 그것을 파악하는 주체는 출판사다. 코들은 그 데이터를 제공하는 쪽이다.

### 혼동되는 상품 관계

가장 위험한 혼동은 AIDT를 코들 상품 카드로 배치하는 것이다. 근거는 세 가지다.

1. 대금이 학교가 아니라 출판사에서 코들로 들어온다 `[source: S-040 / E-043]`
2. 코들 빌드에서 출판사 로그인 버튼과 교실 가입·초대 기능이 의도적으로 제거돼 있다 `[source: S-083 / E-082]`
3. 대외 안내·CS 창구가 AIDT 포털의 출판사 정보로 정의돼 있다 `[source: S-044 / E-047]`

### 최상위 카드/탐색 label 후보

- `AIDT 교육자료` (정본)
- `AI 디지털 교육자료` (약관·실적 표기와 일치)

### 아직 공개 카피로 쓰면 안 되는 표현

- 출판사별 공식 상품명. 확인되지 않았다
- `AIDT 포털` 명칭. 2026-08-12 기준 변경 중이다 `[source: S-082 / E-048]`
- 정산 금액·계약 구조. 전액 대외 비공개 `[source: S-040 / E-043]`
- 출판사 로고·교재 이미지. 사용 권리가 확인되지 않았다

더 심각한 혼동은 캠프와 해커톤 사이다. 해커톤 문의 창구로 들어온 고객이 캠프 형식을 요청한 사례 `[source: S-030 / E-035]`, 해커톤 상담 중에 캠프의 존재를 처음 알고 제3의 요구로 확장한 사례 `[source: S-054 / E-061]`가 모두 관찰됐다.

### 최상위 카드/탐색 label 후보

`찾아가는 AI 체험학교 패키지`와 `디지털 새싹형`은 카드 label로 쓰지 않는다. 상세에서 운영 형태로만 설명한다.

`대회`라는 label이 실제 수요의 일부만 담는다. `시상 계획 없음`인 건이 존재하는 이상 심사·시상을 필수 요소로 표현하면 안 된다.

### 혼동되는 상품 관계

- `짓다`가 코들과 별개 브랜드로 노출되고 있다. 고객은 `짓다 해커톤 대회 홍보내용으로 접하신 듯` `[source: S-022 / E-027]`이라 기록될 정도로 짓다 경로로 먼저 만난다
- 한 행사에서 코들과 짓다를 함께 쓰면 참가자와 교사 모두 혼동한다 `[source: S-037 / E-040]`

### 최상위 카드/탐색 label 후보

- `바이브코딩 해커톤 대회` (정본, 현행 폼 표기와 일치)
- 대안: `바이브코딩 해커톤` (`대회`를 빼면 방과후·생기부 수요를 배제하지 않음)

### 아직 공개 카피로 쓰면 안 되는 표현

- 기준가 400만원, 할인 관행 `[source: S-061 / E-070]`
- 매출·이익률 수치 `[source: S-057 / E-065]`
- 학교명이 포함된 사례 페이지의 재사용 `[source: S-008 / E-012]`. 사용권이 확인되지 않았다
- `생기부`, `학생부 기록 연계` 표현. 관찰은 됐으나 교육 규정상 민감하며 owner 승인이 필요하다

## 7. 짓다 플랫폼 (O-006)

- 정본상 P-006의 하위 구성이다
- 그러나 실제로는 `landing.jitda.io` 별도 랜딩, 별도 사례 페이지, 별도 문의 채널을 갖고 있다
- 2026-07-29 시점에 `짓다, 코들-해커톤 렌딩 저장소 합치기` 과업이 Notion에 존재한다. 통합 방향으로 움직이고 있으나 완료 여부는 확인되지 않았다
- 허브에서 짓다를 어느 수준까지 노출할지는 owner 결정 사항이다. 현재 고객 인지가 짓다 쪽에 먼저 형성된 사례가 있으므로 완전히 숨기면 검색 유입이 끊긴다

## 8. 종합 권고

1. 최상위 카드 label은 정본 6개 명칭을 쓴다. 세 어휘 체계 중 정본이 가장 중립적이고 상품 간 층위가 균일하다.
2. `기본 플랜 / 콘텐츠 이용권`은 카드 label이 아니라 구매 구성 단계의 어휘로 내린다. 이미 가격 페이지가 그 구조다 `[source: S-017 / E-022]`.
3. `모델`, `플랜`, `구독권`, `번개`는 공개 화면에서 쓰지 않는다.
4. `디지털 새싹형`, `찾아가는 AI 체험학교 패키지`, `AI 플랜`은 레거시로 분류하고 문의 폼에서도 정리 대상으로 올린다.
5. 캠프와 해커톤은 이름이 아니라 `무엇을 만들어 나가는가`로 구분해야 한다. 혼동 사례가 이름 때문이 아니라 산출물 설명 부재에서 나왔다.
