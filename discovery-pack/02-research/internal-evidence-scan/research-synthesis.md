- 작성일: 2026-08-24
- 조사 대상: Team Monolith Slack workspace `monolith-keb2010`, Team Monolith Notion workspace
- 근거 파일: `00-search-log.md`, `source-register.csv`, `evidence-extracts.csv`, `budget-trigger-evidence.csv`, `approval-evidence-inventory.csv`, `buying-group-jtbd.md`, `offering-vocabulary-findings.md`, `commercial-routing-findings.md`, `coverage-and-gaps.md`
- 정본 준수: R-013의 폐기된 해석을 복원하지 않았다. C-016/C-017은 계속 prohibited로 취급했다. AIDT를 코들 직접 판매로 기술한 곳이 없다.

## 1. 조사 범위와 한계

Slack 키워드 검색 12회와 채널 이력 조회 1회, Notion 제목 검색 7회를 수행했다. 확보한 source는 83건(Slack 70, Notion 13), 중복 제거 후 독립 event는 53건, 채택 extract는 92건이다. 등급 분포는 A-direct 28건, B-near-direct 39건, C-internal-summary 25건이며 D-hypothesis는 결론 근거로 사용하지 않았다. 이 수치는 `validate_internal_scan.py` 실행 결과와 일치한다.

세 가지 구조적 한계가 있다.

첫째, Notion 검색이 제목만 매칭한다. 대조 검색으로 `부장`을 넣었을 때 결과가 1건뿐이었던 것이 근거다. 본문에만 존재하는 구매그룹·예산 서술은 Notion 쪽에서 놓쳤을 가능성이 높다 `[source: S-005 / E-005]`.

둘째, Notion CRM 전수 조회에 실패했다. `API-query-data-source`가 딜 DB와 소통 DB 모두에서 `invalid_request_url`을 반환했다. 소통 로그는 제목 검색에 걸린 row만 확보했으므로 예산·보류 사유의 실제 분포는 알 수 없다.

셋째, 고객 직접 발언의 대부분이 채널톡과 전화에 있고 Slack에는 그 요약만 남는다. 그래서 이번 조사의 A-direct는 대체로 문의 폼 제출 원문, 견적·정산 기록, 파트너가 보낸 문서다. 고객이 스스로 한 말은 대부분 B-near-direct다.

`검색한 위치와 검색어에서는 확인되지 않음`으로 남긴 항목은 `coverage-and-gaps.md` 4절과 `00-search-log.md` 6절에 있다.

## 2. 기존 고객의 실제 코들 인식

기존 고객이 코들을 무엇으로 보는지에 대한 직접 진술은 드물다. 대신 행동에서 두 가지가 드러난다.

**코들은 먼저 `코스웨어`로 인식된다.** 정보 AIDT를 다른 업체로 채택한 학교가 코들을 사려면 `정보aidt를 선택하지 않고 코들을 (코스웨어로서) 구매하기 위한 당위성이 필요함`이라고 기록됐다 `[source: S-051 / E-056]`. 즉 코들은 AIDT의 대안 코스웨어라는 카테고리 안에서 비교된다. historical 기록이지만 카테고리 인식의 출발점을 보여준다.

**프로그램 상품은 별도 브랜드로 인지되는 경우가 있다.** 한 고객은 `짓다 해커톤 대회 홍보내용으로 접하신 듯`으로 기록됐다 `[source: S-022 / E-027]`. 코들이 아니라 짓다를 먼저 만난 것이다. 프로그램 라인이 코들 브랜드 밖에서 인지되고 있다는 뜻이며, 이는 인식 전환 목표에 양날이다. 유입은 늘지만 `코들 = 전 범위 파트너`라는 인식은 생기지 않는다.

**교육청 단위에서는 플랫폼 벤더 비교군에 들어가 있다.** 한 교육청 산하기관은 기존 벤더 재계약 부담 때문에 `다른 곳과 비교 후 괜찮은 업체로 변경하는 것을 고려하고 있다`고 기록됐다 `[source: S-053 / E-059]`. 여기서도 비교 축은 정보교과 플랫폼이지 AI 교육 전 범위 파트너가 아니다.

세 관찰 모두 정본의 전제 `현재 인식 = 수업에 사용하는 소프트웨어`와 어긋나지 않는다. 다만 이 조사만으로 인식 전환의 필요성을 정량 증명할 수는 없다.

## 3. 소프트웨어 외 상품 발견·교차판매 증거

### 3-1. 발견은 실제로 일어난다. 다만 우발적이다

가장 명확한 사례다. 한 영재학교 교사가 해커톤 상담 중에 캠프의 존재를 처음 알았다. `짓다 해커톤 이야기를 하다가 팀모노에서 캠프도 한다. 해서 해커톤은 아니고 영재고에서 알고리즘 대회를 해야 하는데 이것도 가능할까 싶어서 문의해본다 하십니다` `[source: S-054 / E-061]`.

이 한 문장에 프로젝트가 노리는 연쇄가 모두 들어 있다. 상품 하나를 문의하다가 다른 상품의 존재를 알게 되고, 자기 상황(알고리즘 대회)에 연결하고, 즉시 추가 문의를 만들었다. 문제는 이 발견이 화면이 아니라 사람의 말에서 일어났다는 점이다. 허브가 없으면 상담 담당자가 말해줄 때만 발생한다.

### 3-2. 잔여 예산 교차판매는 관찰된 행동이다

`예산 댕겨서 470만원 프로로 진행하고 남은 예산은 씨마스 교과서에 투자 예정` `[source: S-025 / E-031]`. 라이선스를 먼저 확보하고 남은 돈을 콘텐츠 이용권으로 돌린 실제 사례다.

CRM 소통 로그에는 더 직접적인 표현이 있다. `해커톤 짓다와 코들을 함께 털어 예산 사용 희망함` `[source: S-020 / E-025]`. 같은 건의 통화 기록은 `코들 사용료 + 해커톤 대회 예산이 한정되어 있어, 예산 활용에 고민이 큼` `[source: S-022 / E-027]`이다.

여기서 중요한 반전이 있다. 고객은 `남은 예산으로 하나 더`가 아니라 `한정된 예산을 어디에 나눌까`를 고민한다. 두 상품이 서로 보완재가 아니라 경쟁재로 작동한 것이다 `[source: S-019 / E-024]`.

`남은 예산` 메시지 자체는 시장 관행이기도 하다. 내부에서도 `요즘 에듀테크 업체들에서 학교에 남은 예산 털어라~ 라는 sns광고가 자주 보이는데요, 남은 예산은 언제까지 털수 있는 건가요?`라고 물었고 답을 갖고 있지 않았다 `[source: S-048 / E-053]`.

### 3-3. 교차판매가 실제로 성립한 조합

| 조합 | event | 근거 |
|---|---|---|
| 라이선스 -> 씨마스 이용권 | EV-007 | S-025 / E-031, S-026 / E-032 |
| 라이선스 -> 해커톤 | EV-005 | S-019 / E-024 |
| 오리지널 이용권 + 씨마스 이용권 동시 | EV-007 | S-026 / E-032 |
| 교육청 라이선스 논의 -> 해커톤 제안 | EV-025 | S-053 / E-060 |
| 프로그램 -> 라이선스 (역방향) | EV-013 | S-034 / E-039 |
| 해커톤 상담 -> 캠프 발견 -> 제3 요구 | EV-026 | S-054 / E-061 |

역방향 사례가 있다는 점이 중요하다. 교육청 지침이 프로그램 위탁을 막자 수요가 플랫폼 활용으로 이동했고, 한 달 뒤 라이선스 문의로 이어졌다 `[source: S-034 / E-039]`. 허브가 상품을 나란히 두면 이런 대체가 자연스러워진다.

## 4. 역할별 구매 흐름

가장 완결된 체인은 광주동신여중 해커톤 건이다 `[source: S-006 / E-008]` `[source: S-007 / E-009]` `[source: S-008 / E-012]`.

```text
담당교사(제안) -> 부장교사(검토) -> 기안 결재 -> 행정실(계약·지출)
             -> 코들 운영 -> 교육청 커넥팅데이에서 사례 확산
```

여기서 배울 것은 반대의 위치다. 계약을 막은 것은 상품도, 가격도, 교육적 효과도 아니었다. `유일한 허들은 강사비 규정으로 50만원 책정을 행정실이 반대하는 것` `[source: S-006 / E-008]`이었고, 해결책은 항목명을 여비·자문비로 바꾸는 것이었다.

또 하나. 교사와 행정실이 인식한 계약 방식이 달랐다. `선생님께서 말씀하셨을 땐 수의계약으로 진행하신다고 하셨는데 행정실에서는 s2b로 하신다고 합니다` `[source: S-007 / E-009]`. 제안자는 계약 절차를 정확히 모른다.

기관형은 다르다. 첫 접점이 결정권자가 아니다. `자기는 그냥 연구원이고 결정권이 없으며 보고를 위한 견적이다를 강조하셨습니다` `[source: S-033 / E-038]`.

교육청형은 또 다르다. 승인 관문이 행정이 아니라 교과 타당성이다. 교사자문단이 `바이브코딩을 통해 학생들의 문제해결 사고력을 평가할 수 있을지 모르겠다`, `정보과 행사인데 그 취지를 전혀 살리지 못하는 방식인 것 같다`고 제기했다 `[source: S-038 / E-041]`.

세 세그먼트가 서로 다른 설득 대상을 갖는다. 학교는 행정실, 기관은 결정권자 접근, 교육청은 교과 전문가다.

품의와 행정실 결재는 별도 단계로 관리된다. `월요일까지 품의 결재되어서 15일 월요일에 행정실 결재 진행이 가능하시는 조건으로 마감된다고 알려 주세요` `[source: S-078 / E-052]`.

교감·교장의 직접 발언은 한 건도 확보하지 못했다. 결재선 4단계 모델 `담당교사(기안) -> 부장 -> 교감(검토) -> 교장(결재)` `[source: S-005 / E-005]`은 내부 기획 문서의 해석이며 C 등급이다. 이 모델을 화면 설계의 전제로 삼기 전에 owner 확인이 필요하다.

## 5. 상품별 구매 trigger·예산·시기

### P-001 코들 라이선스

시작은 대체로 소액·소규모 시범이다. `차학기 코들 구매를 위해 남은 한달간, 한 학급에서 코들 사용 예정. 학교 잔여 예산으로 프로 제공해드림` `[source: S-051 / E-056]`. Basic에서 Pro로 가는 경로가 무료 체험이 아니라 잔여 예산을 쓴 유상 시범이었다는 점이 관찰이다.

예산은 파편적이다. `정보예산 50만원` `[source: S-071 / E-079]`부터 고교학점제 예산 `5명 선생님에게 각각 28만원씩 사용할 정도` `[source: S-015 / E-021]`, 교육청 잔여 예산 3천만원 일괄 구매 `[source: S-050 / E-055]`까지 두 자릿수 배 차이가 난다.

시기는 세 개의 분기점이 관찰된다. 추경(7월) `[source: S-068 / E-077]`, 학기 시작 전 계약(계약기간 2026-08-24~2027-02-28) `[source: S-021 / E-026]`, 연간 예산 수립(교육청, 1~12월) `[source: S-053 / E-059]`.

보류 사유는 대부분 예산 규모 불일치다. `120만원 이하의 예산으로 1학기 사용을 원하는 비현실적인 상황` `[source: S-067 / E-076]`.

### P-002 코들 오리지널 콘텐츠

단독 계기를 보여주는 event가 없다. 관찰된 것은 전부 라이선스와의 상대적 선택이다. `AI 655만원 PRO 350만 중 예산에 맞게 구매 예정` `[source: S-027 / E-033]`, `예산문제로 일단 PRO 계약을 50%할인으로 하고 추후 180만원에 AI 업그레이드 해 주기로` `[source: S-065 / E-074]`.

즉 오리지널 콘텐츠는 예산이 남으면 붙고 모자라면 미뤄지는 위치에 있다. 이는 허브에서 이 상품을 어떻게 배치할지에 직접 영향을 준다. 독립 발견 단위로 두더라도 구매 시점은 라이선스에 종속된다.

### P-003 씨마스 인공지능 기초

계기가 교재 채택과 직결된다. 영업 타깃 자체가 `부산 22개교 씨마스 인기초 채택학교 리스트` `[source: S-016 / E-085]`다.

예산은 소액이고 진입 장벽이 낮다. `고등학교는 고교학점제 예산이 내려온다. ... 따라서 씨마스 인기초 구매 자체가 부담스럽지는 않아진다. 왜냐 돈이 별로 안나가기 때문에 예산도 얼추 있음. 하지만 같은 의미로 많은 학생이 듣지 않으므로,, 어느 정도 팔려서는 의미있는 매출이 안나온다` `[source: S-015 / E-021]`.

보류 사유는 콘텐츠 실물 확인이다. `인공지능 기초 콘텐츠 확인 필요. 예산 한정됨` `[source: S-069 / E-078]`. 그래서 웹전시와 단원별 데모 URL이 먼저 열렸다 `[source: S-013 / E-020]`.

### P-004 AIDT 교육자료

학교 측 구매 trigger는 코들 기록에 없다. 관찰되는 것은 출판사 측 사정이다. `AIDT 가격(인당 4~5만원)은 일반 학교엔 부담. 선도학교도 어려움. 적정가는 연 1~2만원 수준으로 의견 일치` `[source: S-045 / E-049]`.

한 발행사의 정보 과목 AIDT는 2026년 총 2개 고등학교가 구독한다 `[source: S-042 / E-045]`. 규모가 매우 작다.

시기·예산 정보는 확인되지 않았다.

### P-005 AI 집중캠프

trigger가 명확하다. 예산은 있는데 실행 역량이 없는 상태다.

`AI중점학교 예산으로 1억 정도 내려와서 정보 시수를 늘렸어야 했는데, 천안중이 정보 시수를 못 늘려서 학교자율시간에 모든 것을 정보나 AI로 넣었는데 수업할 사람, 방법이 없어서 박정미 선생님이 제안했었던거라고 합니다` `[source: S-001 / E-001]`.

기관형에서도 같은 구조다. `세부 기획 그냥 다 맡아서 해주면 좋다고 함. 이런 행사 해본적이 없어서 감을 못 잡고 있음` `[source: S-032 / E-037]`.

시기는 예산 소진 마감과 연동된다는 내부 해석이 있다 `[source: S-005 / E-006]`. 다만 이는 C 등급이며 고객 발언으로 확인되지 않았다.

가격은 이동 중이다. 첫 계약 7,434,000원 `[source: S-002 / E-003]`은 원가 분석 결과 적자였고 `[source: S-003 / E-004]`, 재산정으로 총액이 200~300만원 상승했다 `[source: S-004 / E-087]`.

### P-006 바이브코딩 해커톤 대회

trigger가 가장 다양하다.

- 생활기록부 기재 근거: `고3들 기말고사 끝나고 생기부 적어주기 위한 행사 / 시상 계획 없음` `[source: S-029 / E-034]`
- 방과후 수업: `20시간정도 아이들과 방과후 수업 운영하고 싶음` `[source: S-024 / E-030]`
- 전면 위탁: `중점학교 예산이 존재하고 그냥 돈으로 편하게 할일을 처리하고 싶으신 느낌` `[source: S-059 / E-067]`
- 교육청 사업: 교사자문단 심사 기준 설계까지 포함 `[source: S-038 / E-041]`

예산 출처가 명시된 사례가 가장 많다. 디지털선도학교 760만원 `[source: S-029 / E-034]`, AI 중점학교 `[source: S-060 / E-069]`, 예산 상한 300만원 `[source: S-006 / E-008]`.

견적 변수도 가장 구체적이다. 인원, 진행 시간 구성(튜토리얼·본행사·발표), 멘토 수, 사전교육 포함 여부, 교사팀 참여 시 추가 요금 `[source: S-058 / E-066]`. 기관 규모에 따라 계약 규모가 10배 이상 차이 난다 `[source: S-057 / E-065]`.

## 6. 내부 승인에 필요한 증거

`approval-evidence-inventory.csv`에 18개 항목을 정리했다. 핵심은 세 가지다.

**첫째, 견적서의 실제 용도는 구매가 아니라 내부 협의다.** `내부 협의를 위한 견적서 희망함` `[source: S-022 / E-027]`, `보고를 위한 견적이다를 강조하셨습니다` `[source: S-033 / E-038]`. 견적서가 승인 문서로 쓰이고 있다.

**둘째, 견적서는 항목 조정이 가능해야 한다.** 학교 규정이 특정 항목명을 거부할 수 있기 때문이다 `[source: S-006 / E-008]`. 한 고객은 `견적서 버전 2개로 송부 바람. (세부내역 있는 것과 없는 것)`을 요청했다.

**셋째, 행정실이 진짜로 신경 쓰는 것은 감사와 차년도 예산이다.** `학교장터의 경우 행정 건정성이 수요기관 감사평가의 영역에 해당됩니다. 정산 이후 시스템상 마지막 단계에 도달하지 못한 경우 패널티 ... 감사 걸리면 다음 예산 받기 힘들어집니다` `[source: S-047 / E-051]`.

이 세 가지는 모두 화면 앞단이 아니라 CTA 이후의 자료다. 허브의 역할은 발견이고, 승인 자료는 문의 이후 단계에서 제공된다.

## 7. 상품 vocabulary와 오해

상세는 `offering-vocabulary-findings.md`에 있다. 종합 관점의 결론만 옮긴다.

내부에 세 개의 어휘 체계가 공존한다. 과금 구조 어휘(모델·플랜·구독권·번개), 대외 판매 어휘(기본 플랜·콘텐츠 이용권), 정본 어휘(코들 라이선스·코들 오리지널 콘텐츠 등)다 `[source: S-011 / E-015]` `[source: S-017 / E-022]`.

콘텐츠 이용권을 상품으로 분리하자마자 명칭 충돌이 발생했고 브랜드 접두어로 해결했다. `Cmass AI, AI 이렇게 표기되는게 약간 어색하고 혼돈되는 네이밍이라 혹시 기존 AI 플랜을 'Codle AI'로 변경해도 될까요?` `[source: S-018 / E-023]`. 허브가 여러 이용권을 나란히 놓으면 같은 문제가 재발한다.

가장 반복되는 오해는 캠프와 해커톤이다. 해커톤 문의 창구로 들어와 캠프 형식을 요청한 사례 `[source: S-030 / E-035]`, 해커톤 상담 중 캠프를 처음 알게 된 사례 `[source: S-054 / E-061]`, 한 행사에서 두 플랫폼을 섞어 참가자와 교사가 모두 혼동한 사례 `[source: S-037 / E-040]`가 있다.

혼동의 원인은 이름이 아니라 산출물 설명 부재다. 고객이 실제로 구분하는 축은 `학생이 무엇을 만들어 나가는가`다.

## 8. AIDT·Pro 콘텐츠 routing

상세는 `commercial-routing-findings.md`에 있다.

**AIDT.** 대금이 학교가 아니라 출판사에서 코들로 들어온다 `[source: S-040 / E-043]`. 발행사가 구독 학교를 파악하고 코들에 데이터를 요청한다 `[source: S-042 / E-045]`. 대외 안내·CS 창구는 AIDT 포털의 출판사 정보다 `[source: S-044 / E-047]`. AIDT 배포본은 코들 민간 기능이 의도적으로 제거된 별도 산출물이다 `[source: S-083 / E-082]`. 정본 CR-011과 완전히 일치하며, 코들 견적 CTA를 붙일 근거는 어디에도 없다.

주의할 점 두 가지다. 출판사별 체험 계정을 내부에서도 즉시 확보하지 못했다 `[source: S-081 / E-081]`. 포털 명칭이 2026-08 기준 변경 중이다 `[source: S-082 / E-048]`. 지금 화면을 만들면 링크 자리만 잡고 비워 둬야 한다.

**Pro 필수 콘텐츠.** 정본 CR-001/CR-002가 실제 판매 정책과 일치한다. `코들 프로 없이 인기초 플랜만 살 수는 없음` `[source: S-010 / E-013]`.

이미 화면이 이 관계를 구조로 강제하고 있다. 가격 페이지가 `기본 플랜 + 콘텐츠 이용권 추가` 구조로 개편됐고, 문의 폼도 `코들 구독 (Pro 플랜 + 콘텐츠 이용권)`이라는 하나의 묶음 안에서 이용권을 체크하게 돼 있다 `[source: S-017 / E-022]` `[source: S-019 / E-024]`. 경고 문구가 아니라 폼 구조로 강제한 방식이며, 허브도 이를 승계하는 편이 안전하다.

이 구조가 실제로 작동한다는 확인도 있다. 한 고등학교의 제출 기록은 씨마스 이용권 선택 시 1인 기준가 30,000원 `[source: S-080 / E-092]`, 다른 중학교는 Codle AI 선택 시 40,000원 `[source: S-079 / E-091]`으로 계산됐다. 30,000원은 파트너 합의값인 Pro 20,000원 + 인기초 10,000원과 정확히 일치한다 `[source: S-010 / E-013]`. 정책과 화면이 어긋나 있지 않다.

다만 운영 준비가 따라가지 못한다. 학기 중 이용권 추가 구매 시 구독권 재배정이 현 구조에서 대응되지 않는다 `[source: S-076 / E-058]`. 같은 학생이 여러 교실에 있으면 구독권이 중복 차감된다 `[source: S-052 / E-057]`. 허브가 교차판매를 적극 유도하면 이 제약이 CS 문제로 돌아온다.

## 9. 랜딩 구조에 반영 가능한 근거 있는 원칙

1. **여섯 상품을 최상위 발견 단위로 두되, AIDT만 행동 유형이 다르다는 것을 시각적으로 드러낸다.** 다섯은 견적·상담, AIDT는 출판사 안내다 `[source: S-040 / E-043]` `[source: S-019 / E-024]`.
2. **문의 진입점은 하나로 유지하고 다중 상품 선택을 지원한다.** 이미 폼이 그 구조이고 실제로 라이선스와 해커톤을 한 번에 제출한 사례가 있다 `[source: S-019 / E-024]`.
3. **CTA 문구는 `구매`가 아니라 `내부 검토용 견적`에 가깝게 둔다.** 견적서가 승인 문서로 쓰이고 있다는 관찰에 근거한다 `[source: S-022 / E-027]` `[source: S-033 / E-038]`.
4. **캠프와 해커톤은 이름이 아니라 산출물로 구분한다.** 혼동 사례가 반복되며 원인이 산출물 설명 부재다 `[source: S-030 / E-035]` `[source: S-054 / E-061]`.
5. **해커톤을 `대회`로만 표현하지 않는다.** 시상 계획이 없는 계약, 방과후 수업 용도 계약이 실제로 존재한다 `[source: S-029 / E-034]` `[source: S-024 / E-030]`.
6. **콘텐츠 이용권은 발견 단계에서 독립 카드로, 구매 구성 단계에서 Pro 종속으로 다룬다.** 정본 CR-001/CR-002와 현행 폼 구조가 이미 그 방식이다 `[source: S-010 / E-013]` `[source: S-017 / E-022]`.
7. **씨마스 카드는 교재 연계와 교사 업무 부담 감소를 함께 제시한다.** 파트너가 교사에게 실제로 보낸 문구가 그 두 축이다 `[source: S-014 / E-019]`.
8. **콘텐츠 이용권 카드의 1차 CTA는 미리보기여야 한다.** 보류 사유가 콘텐츠 실물 미확인이고 웹전시가 그 대응으로 만들어졌다 `[source: S-069 / E-078]` `[source: S-013 / E-020]`.
9. **프로그램 카드에 규모별 운영 형태를 노출한다.** 학교가 자기 규모를 먼저 대입한다 `[source: S-005 / E-088]` `[source: S-060 / E-069]`.
10. **행정·조달 정보는 CTA 이후 단계로 내린다.** 학교장터 물품번호, 계약 임계값, 견적 항목 조정은 발견을 방해하지 승진시키지 않는다 `[source: S-046 / E-050]` `[source: S-007 / E-009]`.
11. **문의 폼에 예산 사업명 입력을 추가한다.** CRM 딜 카드에 `예산출처` 필드가 이미 있으나 비어 있다 `[source: S-021 / E-026]`. 이번 조사가 `확인되지 않음`으로 남긴 칸을 다음 분기에 스스로 채울 수 있다.
12. **짓다 브랜드 경로를 끊지 않는다.** 고객이 짓다로 먼저 인지한 사례가 있다 `[source: S-022 / E-027]`.

## 10. 아직 결정하면 안 되는 것

1. **가격 노출.** Pro 정가 22,000원과 실제 발행 단가 10,000~13,000원이 상시 괴리된다 `[source: S-017 / E-022]` `[source: S-062 / E-071]`. 캠프·해커톤 가격은 재산정 중이다 `[source: S-004 / E-087]`. 어느 것도 공개 승인된 바 없다.
2. **성과 수치.** 캠프 만족도 수치는 인용 허가가 아직 확보되지 않았다고 내부 문서 스스로 밝히고 있다 `[source: S-005 / E-006]`. 프로그램 매출·이익률은 대외 인용 금지다 `[source: S-057 / E-065]`.
3. **기관명·사진·로고.** 전북·광주·천안 사례의 사용권이 확인되지 않았다 `[source: S-008 / E-012]`. 씨마스 교재 표지·이미지, 출판사 로고도 마찬가지다.
4. **파트너 주장의 승계.** `국내 고교 정보 수업 점유율 1위`는 파트너의 표현이며 코들 화면에 옮기려면 별도 확인이 필요하다 `[source: S-014 / E-018]`.
5. **AIDT의 상시성.** 제도적 지위가 2025-05 정책 변경으로 흔들렸고 계약이 재정의 중이다 `[source: S-075 / E-083]`. 출판사 측은 서비스 중단 가능성까지 언급했다 `[source: S-045 / E-049]`. 안정 상품처럼 설명하면 안 된다.
6. **AIDT 외부 링크.** 출판사별 상품명·구매 URL·체험 경로가 확인되지 않았고 포털 명칭도 변경 중이다 `[source: S-081 / E-081]` `[source: S-082 / E-048]`.
7. **씨마스 CTA.** 총판 위탁판매가 2026-09 개시 예정이라 채널 충돌 가능성이 있다 `[source: S-010 / E-014]`.
8. **학교형·교육청형 패키지 정의.** 정본이 요구하는 구분이 내부 문서에서 확인되지 않았다. 대신 규모별(학급형·학년형·전교형) 축이 관찰됐다 `[source: S-005 / E-088]`. 어느 축이 실제인지 owner 확인 전에는 IA에 반영하지 않는다.
9. **결재선 모델.** 담당교사 -> 부장 -> 교감 -> 교장 4단계는 C 등급 내부 해석이며 교감·교장 직접 발언이 0건이다 `[source: S-005 / E-005]`.
10. **교차판매 유도 강도.** 학기 중 이용권 추가 구매의 운영 대응이 아직 안 된다 `[source: S-076 / E-058]` `[source: S-052 / E-057]`. 발견을 늘리기 전에 운영 준비 상태를 owner와 맞춰야 한다.
11. **`생기부` 관련 표현.** 관찰은 됐으나 교육 규정상 민감하며 승인 없이 공개 카피로 쓰지 않는다 `[source: S-029 / E-034]` `[source: S-014 / E-019]`.
12. **최종 카드 순서와 내비게이션.** 이 조사는 발견 구조를 검증하지 않았다. 저충실도 구조 테스트가 선행되어야 한다.
