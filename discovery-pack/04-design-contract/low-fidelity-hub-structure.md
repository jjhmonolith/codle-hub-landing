## 1. 구조 목표

1. 첫 화면부터 코들이 라이선스 외 상품도 제공한다는 사실을 발견시킨다.
2. 여섯 상품을 같은 최상위 탐색 층위에 둔다.
3. 상품을 자기 수업·사업 상황에 연결하게 한다.
4. 콘텐츠의 Pro 필수 관계는 발견 후 구매 구성에서 설명한다.
5. AIDT는 다른 카드와 같은 위치에서 발견시키되 행동은 출판사 안내로 분리한다.
6. 캠프와 해커톤은 이름보다 활동·산출물로 비교한다.
7. 직접 판매 5개는 하나의 다중 선택 문의로 보낸다.

## 3. 핵심 상호작용

### 상품 선택

- 카드의 `문의에 담기`를 누르면 HUB-08 체크박스가 선택된다.
- 여러 상품을 함께 선택할 수 있다.
- AIDT에는 해당 버튼이 없다.

### 상황 필터

- 관련 상품을 앞으로 강조하지만 다른 상품을 숨기지 않는다.
- 목적은 추천이 아니라 새로운 상품 발견이다.

### AIDT 안내

- `출판사 안내 보기`는 현재 설명 패널만 연다.
- 최신 URL을 확보하기 전 외부 링크처럼 보이는 가짜 버튼을 만들지 않는다.

### 문의

- 선택한 상품 수를 보여준다.
- 가격 계산은 보여주지 않는다.
- 예산 사업명/출처는 선택 입력이다.
- 실제 전송은 endpoint 확인 전 prototype 상태로 둔다.

## 4. 반응형 구조

- Desktop ≥ 1024px: 카드 3열, 프로그램 비교 2열
- Tablet 768–1023px: 카드 2열
- Mobile < 768px: 카드 1열, 동일 DOM 순서 유지
- 상품 filter는 줄바꿈하며 가로 스크롤에 의존하지 않는다.
- 모든 버튼·체크박스 터치 영역은 최소 44×44px

## 5. 구조 검증 과제

1. 코들에서 라이선스 외 상품 세 개를 찾아 말할 수 있는가?
2. 콘텐츠 이용권을 Pro 없이 살 수 있다고 오해하지 않는가?
3. AIDT를 코들 견적 상품으로 오해하지 않는가?
4. 캠프와 해커톤을 활동 결과로 구분할 수 있는가?
5. 라이선스와 해커톤을 한 문의에 함께 담을 수 있는가?
6. 가격·기관명·성과 수치가 노출되지 않았는가?

## 6. 아직 디자인하지 않는 것

- 색상·서체·일러스트·사진 방향
- 카드의 최종 시각적 우선순위
- 최종 H1과 상품 설명 카피
- 실제 기관 사례
- 가격표
- 실제 폼 API 연결
