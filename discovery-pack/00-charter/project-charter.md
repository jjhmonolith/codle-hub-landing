## 1. 프로젝트 목적

Codle의 현재 사업·상품·구매 과정을 새로 조사하여, 고객의 인식을 **`코들 = 단순 소프트웨어`에서 `코들 = AI 교육의 전 범위를 서비스하는 파트너`로 전환·확장**한다. 이를 통해 기존 고객이 라이선스 외의 콘텐츠·제휴 상품·교과자료·캠프·해커톤까지 발견하고 **“코들이 이런 것도 하네? 남은 예산으로 이걸 도입하자”**고 판단하게 만드는 교차판매형 상품 허브를 구축한다.

이 허브는 먼저 상품의 존재와 도입 가능성을 발견시키고, 그다음 기관 고객이 내부 검토에 필요한 근거와 적절한 문의 경로로 이동하게 한다. 라이선스와 콘텐츠 이용권의 복잡한 구매 관계가 다른 상품의 발견을 가리지 않도록, `상품 노출 구조`와 `구매 구성 구조`를 분리한다.

이 Charter는 기존 `design-source-pack`의 개정안이 아니다. 기존 Pack은 과거 가설과 재검증 질문을 찾는 참고 자료로만 분류한다. 새 랜딩의 사실·구조·메시지·디자인·측정 정본은 이 `discovery-pack`에서 독립적으로 만든다.

## 3. 검증할 핵심 문제

다음은 아직 확정 사실이 아니라 연구 가설이다.

- 현재 랜딩이 실제 판매 중인 제공 범위 전체를 충분히 발견하게 하는가?
- 주 방문자는 누구이며, 방문자와 최종 승인자는 같은가?
- 방문자가 개인 무료 사용과 기관 도입 중 어떤 일을 하러 오는가?
- 상품/플랜/콘텐츠 이용권/프로그램/제휴 상품을 어떤 관계로 이해해야 하는가?
- 내부 승인에 필요한 가격, 운영, 보안, 사례, 지원 정보가 무엇인가?
- 현재 CTA와 폼이 CRM의 유효 기관 수요로 이어지는가?

## 3-1. 1차 성공 가설

이 허브의 핵심 성공은 사용자가 처음부터 알고 있던 코들 라이선스를 이해하는 데 그치지 않고, **원래 찾지 않았던 두 번째 상품을 발견하여 예산 집행 후보로 검토하는 것**이다.

검증할 주요 신호:

- 기존 고객이 라이선스 외 상품 상세로 진입한다.
- 한 방문에서 서로 다른 상품군을 2개 이상 살펴본다.
- 씨마스·AIDT·캠프·해커톤의 대상, 운영 기간, 예산 판단 정보를 확인한다.
- 비라이선스 상품의 자료 요청·공유·문의가 발생한다.
- CRM에서 기존 고객의 추가 상품 문의와 교차판매 기회가 식별된다.

가드레일:

- 구매 조합 설명이 상품 발견보다 먼저 나오지 않는다.
- 라이선스 중심 navigation 때문에 프로그램·제휴 상품이 하위에 묻히지 않는다.
- 단순 클릭 증가가 아니라 실제 예산 검토·유효 문의·교차판매 기회로 평가한다.

## 4. 이번 Gate 0의 목표

- 현재 운영 화면과 저장소에서 관찰되는 상품·플랜·주장·행동을 원천 receipt와 함께 기록한다.
- 관찰값과 승인값을 분리한다.
- 상품 수·명칭·가격·판매 관계·사례·인증·성과 수치에 소유자와 승인 상태를 부여할 준비를 한다.
- 기존 Source Pack의 내용을 새 정본으로 복사하지 않는다.
- 후속 인터뷰와 데이터 분석에서 답해야 할 질문을 확정한다.

## 5. 이번 Gate 0의 비범위

- 최종 상품 수와 분류 확정
- 페르소나·구매그룹 확정
- 헤드라인, IA, 섹션 순서, CTA hierarchy 확정
- 시각 디자인 또는 코드 구현
- 기존 서비스 문구·가격·성과 수치를 사실로 승인
- 기존 Source Pack의 파일/데이터 이관

## 6. 원천 우선순위

1. 사업 책임자가 승인한 현재 계약·가격·상품 정의
2. 실제 운영 시스템과 CRM/폼 서버의 관찰 가능한 결과
3. 현재 운영 저장소의 버전 고정 코드
4. 실제 고객/영업/CS 인터뷰와 사용성 관찰
5. 현재 공개 서비스 캡처
6. 외부 연구·표준
7. 기존 Source Pack 및 과거 기획 문서 — reference only

충돌 시 더 최신이고 직접적인 1차 원천을 우선하고 `decision-log.md`에 남긴다.

## 7. Gate 0 통과 조건

- [ ] 모든 인벤토리 항목에 receipt ID가 있다.
- [ ] 사용자 노출 가능 claim은 `approved`와 owner가 모두 있다.
- [ ] 가격·성과·보안·수상·사례·고객 로고는 담당자 승인 전까지 `pending`이다.
- [ ] 기존 Source Pack에서 복사한 claim이 없다.
- [ ] 상품 범위와 판매 관계의 미결 질문이 담당자별로 배정됐다.
- [ ] 현재 CTA/폼/분석/CRM 연결의 조사 범위가 기록됐다.

## 8. 다음 Gate로 넘어가는 기준

Gate 0 승인 뒤에만 구매그룹 인터뷰와 카드소팅을 시작한다. 구체 IA·카피·화면 설계는 구매그룹, 상품 관계, 승인 근거가 검증된 뒤 진행한다.
